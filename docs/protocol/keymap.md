# Key mapping

The wire carries macOS virtual keycodes in `keyDown` and `keyUp`. The table and tool are in
[vectors/keymap.json](vectors/keymap.json), generated by [vectors/tools/gen_keymap.py](vectors/tools/gen_keymap.py).

* Windows host: translate the macOS keycode to a set 1 scancode (`keys.*.scancode`, with an `E0` prefix when `extended`) and
  inject with `KEYEVENTF_SCANCODE`. Keycodes 54 to 63 are modifiers (`modifiers`). Command maps to Ctrl so that Mac shortcuts work
  (Command+C becomes Ctrl+C); Option maps to Alt. The `modifiers` bits on a key event (17 shift, 18 control, 19 option, 20 command)
  are applied around the key by the host. Keycode 256 (`windowsKeyCode`) is reserved for the Windows key and is outside the macOS
  range; only send it to a host that declared `hostPlatform: "windows"`.
* Android client: `KeyEvent` codes map to macOS keycodes through `android`. Text from an on-screen keyboard is sent as `textInput`,
  not as keys. Keys with no entry (Insert, media keys) are not sent.
* Function keys F1 to F12 are 122, 120, 99, 118, 96, 97, 98, 100, 101, 109, 103, 111 (`MediaKey.functionKeyCodes`). With the
  `topRowAction` bit (1 << 8) a host SHOULD perform the printed action (brightness, volume, media) instead.

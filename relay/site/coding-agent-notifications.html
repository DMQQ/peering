Get Notified When Claude Code Needs You, on Your iPhone

Start the agent, walk away, and come back only when it actually needs you.

The short version. Peering watches the shells on your Mac. When one stops to ask for something (a coding agent's permission request, a sudo password, a yes or no), your iPhone shows a banner with the question in it. Tap it, and you are in that shell, ready to answer.

The problem with leaving an agent alone

Claude Code, Codex and the rest do their best work while you are somewhere else. Then they stop to ask whether they may run a command, and wait. Nothing tells you. You come back an hour later to find it asked two minutes after you left, and has been sitting on the question ever since.

The same goes for a build that finished, a git push waiting for a key passphrase, or a migration asking you to confirm. The machine is ready for you; you just do not know it.

What Peering does about it

The Mac app reads what your shells print and recognises two kinds of question: a password prompt and a yes or no confirmation. When one appears, the Mac sends a notification to your iPhone through Peering's relay, with the prompt quoted in it so you can tell which agent is asking and what about.

  • It works in Terminal and iTerm windows as well as in Peering's own shells, so you do not have to change how you start your agent.
  • It arrives with the app closed and the phone locked, like any other notification.
  • It alerts once per prompt, and re-arms when you answer, so a question left waiting does not buzz you every few seconds.
  • In Peering's own shells it also tells you when a command that took five seconds or more has finished.

Answer it from the phone

Tap the banner and Peering takes you to the shell or window that asked. Its own shells open full screen, with a key row built for a phone: Escape, Control, Tab, arrows, and word-at-a-time movement. Type y, paste a password from your password manager, or read the diff the agent wants to apply first. If you would rather see the whole desktop, switch to the Mac's screen in the same app.

Private by design

The relay that carries the session cannot read it: your iPhone and Mac each hold their own key, and nothing about the session is stored on a server. There is no account to create. The Privacy Policy says exactly what the relay can and cannot see.

What it costs

The terminal, SSH to your servers, the file browser and being told when a shell is waiting are all free on every plan. Pro ($4.99 a month) or Lifetime ($39.99, paid once) also lifts the 30-minute daily limit on reaching your Mac from another network.

Questions

Which prompts does Peering notice?

Password prompts, including sudo and SSH key passphrases, and yes or no confirmations, which is the shape a coding agent's permission request takes. In Peering's own shells it also tells you when a command that ran for five seconds or more has finished.

Does it work in Terminal and iTerm, or only in Peering's own shell?

Both. Peering watches Terminal and iTerm windows on the Mac as well as the shells it opens itself.

Does the iPhone app need to be open?

No. The Mac sends the banner through the relay, so it arrives with the app closed and the phone locked.

Which plan is it on?

All of them. The terminal, SSH and the alerts work on every plan; a paid plan only lifts the 30-minute daily limit on reaching your Mac from another network.
